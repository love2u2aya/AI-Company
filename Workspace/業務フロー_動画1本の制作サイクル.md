# 業務フロー：動画1本の制作サイクル

**制作期間**: 3日  
**投稿頻度**: 週3〜5本（複数本が並行進行）  
**社長承認**: サムネイル確認後（制作前）・完成後の2回

> **方針：サムネ先行**
> 企画が決まったらまずサムネイルを作り、「これはクリックしたくなるか」を社長が判断してから制作を開始する。
> サムネイルでバズらない企画は動画にしない。

---

## 全体の流れ

```
Day 1【企画＋サムネ確認】         Day 2【制作・三段階並行】              Day 3【仕上げ・公開】
FP 深掘りブリーフ提供              Creator ナレーション原稿（確定）        Editor 編集完了
    ↓                                  ↓（3本同時並行）                        ↓
Planner 企画（FPブリーフ参照）     FP ファクトチェック                    秘書 → 社長承認②
    ↓                              Critic 台本批評（6軸）                       ↓
Critic 企画批評（第1審査）         Slide Designer スライド全件制作         SNS_Manager 投稿
    ↓ PASS のみ通過                    ↓ FP + Critic 両方PASS後
Designer サムネイル案作成          Editor 編集開始（Slide Designerのスライド素材受領後）
    ↓
秘書 → 社長承認①
    ↓
  GO!
```

---

## Day 1：企画＋サムネイル確認フェーズ

### Planner のタスク
1. トレンドワードをリサーチ（YouTube / TikTok / X）
2. 企画案を3〜5本出す
3. 各案に以下を添付して企画書を作成：
   - タイトル案（3パターン）
   - 構成概要（冒頭つかみ30秒・本編・オチ）
   - ターゲット視聴者
   - **サムネイルコンセプト案（必須）**: 文字・顔・色・構図のイメージ
4. `AgentOutput/企画_YYYYMMDD.md` に保存
5. **Critic に審査依頼**

### Critic のタスク（Planner提出から24時間以内）
1. 企画書を5軸（新鮮さ・ターゲット刺さり度・タイトル訴求力・構成実現可能性・タイムリー性）で審査
2. `AgentOutput/批評レポート_YYYYMMDD.md` に判定結果を保存
3. **PASS / CONDITIONAL** → 秘書に提出し次のステップへ
4. **REVISE / REJECT** → 修正指示をPlannerに返却・再提出を求める

### Designer のタスク（Day 1 中に完了・Critic PASS後に開始）
1. Plannerの企画書を受け取り、各企画案のサムネイルを**ラフ案**で制作
2. 1企画につき1〜2案（完成品でなくてよい・判断できる精度でOK）
3. `AgentOutput/サムネイルラフ_YYYYMMDD/` に保存
4. 秘書に提出

### 秘書のタスク
- 企画書＋サムネイルラフをセットで**社長に提出**
- 社長のGO/NG判断を待つ

### ✅ 社長承認①（サムネイル＋企画承認）
> **社長が確認すること**
> - サムネイルを見て「クリックしたいか」を直感で判断する
> - どの企画案でいくか選ぶ（または修正指示）
> - サムネがNGなら企画ごと差し戻しも可

- **GO** → 秘書が制作フェーズを開始・Designerにサムネ本制作を指示
- **NG（サムネ修正）** → Designerに差し戻し・再提出
- **NG（企画から見直し）** → PlannerとDesigner両方に差し戻し

### 承認後：秘書のタスク
- チケットを `TicketManagement/Doing/` に作成
- Creator / Editor に制作開始を指示
- Designer にサムネイル本番制作を指示

---

## Day 2：制作フェーズ（並行作業）

### Creator のタスク
1. 確定したナレーション原稿（FP・Critic両方PASS後）をもとに音声収録
2. `AgentOutput/音声_YYYYMMDD.wav` に保存しEditorに引き渡す
3. ※スライド制作はしない。Slide Designerが担当

### Slide Designer のタスク（Creatorと並行して開始・FP+Critic PASS後）
1. 確定ナレーション原稿を読み込み、**スライドマップ**を作成
2. デザインシステム（カラー・タイポグラフィ・グリッド）に沿って全スライドを制作
3. PowerPointでアニメーション設定
4. MP4書き出し（1920×1080 / 30fps）または静止画+アニメーション指示書を作成
5. `AgentOutput/スライド素材_YYYYMMDD/` に保存
6. **スライド指示書**（スクショ推奨スライドのTC・静止秒数）をEditorに渡す

### Designer のタスク
1. 企画書のサムネイルコンセプトをもとに2〜3案制作
2. `AgentOutput/サムネイル案_YYYYMMDD/` に保存
3. 秘書に提出（社長が後で選ぶ）

### Editor のタスク
1. **Slide Designerからスライド素材を受領後**に編集開始（Creatorの音声と合わせる）
2. テロップ → BGM → SE → エフェクト（スライド自体のデザインは変更しない）
3. Day 3午前中に完成を目指す

---

## Day 3：仕上げ・公開フェーズ

### Editor のタスク
1. 編集を完了し書き出す（MP4・1080p）
2. `FinalOutput/動画_YYYYMMDD_タイトル.md` に完成情報を記録
3. **QC に完成報告**（秘書経由）＋スライド指示書・確定ナレーション原稿を添付

### QC のタスク（Editor納品後）
1. 完成MP4・スライド指示書・確定台本・メタデータ草案が揃っていることを確認
2. 映像チェック（通し視聴1回目：構成・テンポ・テロップ・静止時間）
3. 音声チェック（通し視聴2回目：音量バランス・同期・BGM）
4. 数値突合チェック（台本 vs スクリーン上の数字を全件照合）
5. メタデータチェック（タイトル・概要欄・チャプター・タグ）
6. `AgentOutput/QCレポート_YYYYMMDD.md` を作成
   - **PASS** → SNS_Managerにアップロード許可証を発行・秘書に報告
   - **FAIL** → 差し戻しリストをEditorに送付・チケットを `Waiting/` に移動

### SNS_Manager のタスク（QC PASS後）
1. QC確認済みメタデータ（タイトル・概要欄・タグ）を最終整理
2. YouTube Studioで動画を **非公開** でアップロード
3. サムネイルを設定・エンドカードを設定・チャプターを確認
4. 非公開URLを生成 → 秘書に「社長確認用URL」を送付

### ✅ 社長承認②（非公開プレビュー確認）
> **社長が確認すること**
> - 非公開URLで動画を通しで視聴し、内容・クオリティに問題がないか
> - サムネイルを最終決定する
> - 公開タイミングを指定する

- **GO** → 秘書が SNS_Manager に公開指示＋公開日時を伝える
- **修正** → 該当メンバーに差し戻し（チケットを `Waiting/` に移動）

### QC のタスク（社長承認後・公開前の最終確認）
- SNS_Managerのアップロード完了後、非公開URLでチャプター・サムネイル・リンクを最終確認
- 問題なければ秘書に「公開OK」を報告

### SNS_Manager のタスク（公開処理）
1. 採用サムネイルを `FinalOutput/` に確定保存
2. YouTube Studioでプライバシー設定を「非公開」→「公開」または「スケジュール設定」に変更
3. 公開完了を秘書に報告

### 秘書のタスク
- チケットを `TicketManagement/Done/` に移動
- 社長に完了報告（報告フォーマットを使用）

---

## 並行進行のイメージ（週3〜5本体制）

```
月        火        水        木        金
企画A     制作A     公開A
          企画B     制作B     公開B
                    企画C     制作C     公開C
                              企画D     制作D
```

Planner は毎日企画を出し続け、CreatorとEditorは常に制作中の状態を維持する。

---

## チケットの動き（1本の動画の場合）

```
ToDo → Doing（Day1承認後）→ Waiting（Day3差し戻し時のみ）→ Done（投稿完了）
```
